## 1. 空值哨兵

下列值（去首尾空白后、大小写不敏感）一律视为 **NULL / 空**：

```
空串、-、--、—、–、无、null、none、n/a、na、/、\、
暂无、未知、nan、null值、*、**、???
```

实现：`load_jzh.EMPTY` / `is_empty()` / `clean()`。

## 2. 主键：统一社会信用代码

| 情况 | 规则 |
|------|------|
| 合法 | `^[0-9A-Z]{18}$`（入库前转大写、去空格） |
| 缺失或非法 | 代理键：`N` + `MD5(公司名)[:17].upper()`，共 18 位 |
| 去重 | Doris `UNIQUE KEY(credit_code)` + `sequence_col = fill_score`：**同码多行保留 fill_score 更大（字段更全）的一条** |

`fill_score` = 该行非空源字段个数；回填 street / 坐标时通常 `fill_score + 1` 以覆盖旧行。

公司名为空的行：**丢弃**（计入 bad_rows）。

字符串写入前按 Doris **字节长度**截断（`tb()`），不是按字符数。

## 3. 省份 / 城市 / 区县

### 3.1 省份归一（`PROVINCE_MAP`）

短名 → 标准全称，例如：`浙江`→`浙江省`，`上海`→`上海市`，`广西`→`广西壮族自治区` 等（含港澳台以外省级行政区短名映射）。

### 3.2 兜底省份（`GROUP_PROVINCE`）

源文件目录决定兜底省，用于省份字段为空：

| 目录 | 省份 |
|------|------|
| 江苏所有企业 | 江苏省 |
| 浙江所有企业 | 浙江省 |
| 安徽所有企业 | 安徽省 |
| 上海所有企业 / 上海所有企业-新版 | 上海市 |

### 3.3 月度增量地区串（`load_monthly.parse_region`）

原文如 `江苏-苏州市-吴中区` / `上海-上海市-宝山区`：

- 用 `-` / `—` / `/` 切分；
- 第一段走 `PROVINCE_MAP`；
- 直辖市：二段或三段分别落到「市 / 区」。

城市、区县名称：入库时一般保留源表原文（再经空值清洗与截断），不做拼音或简称强制展开。

## 4. 登记状态归一（`STATUS_MAP`）

归一到有限类（业务默认筛「存续」）：

| 原文示例 | 归一 |
|----------|------|
| 存续、正常、在业、开业、在营、在册、存续/在业、存续（在营…）、迁入 | **存续** |
| 迁出 | **迁出** |
| 注销、已注销 | **注销** |
| 吊销、吊销未注销、吊销已注销、撤销 | **吊销** |
| 清算 | **清算** |
| 停业 | **停业** |

未命中映射表的原文：按实现可能保留原串或空，以 `load_jzh` 当前处理为准。

## 5. 注册资本 / 实缴资本

解析模式：`数字 + 可选(万|亿) + 可选币种`。

1. 去掉千分位逗号；  
2. 单位：`万`→×1，`亿`→×10000，**无单位按「元」→×0.0001 万元**；  
3. 币种按固定汇率折算 **人民币万元**（`FX`：美元 7.2、港元 0.92、欧元 8.0…）；  
4. **脏数据纠偏**：  
   - 单位为「万」且 `数字×汇率 >= 1e8`（约 ≥1 万亿），或 `>= 1e7`（约 ≥1000 亿）且非央企白名单 → 按「元」重算；  
   - 回修脚本另处理：≥1000 亿非央企、≥100 亿微型、工会/学校/营业厅等挂靠名；  
   - **只允许改小，禁止放大**；  
5. 结果仍 `> 5e8` 万元 → **资本置空**（保留币种若已解析）；  
6. 保留 `capital_raw` 原文备查。

回修脚本：`etl/repair_capital.py`（按 `capital_raw` 重算 `capital_wan`）。

## 6. 日期

- 优先匹配：`YYYY-MM-DD` / `年/月/日` / `.` 分隔等；年份限 1800–2100；  
- Excel 序列号：约 `20000–60000` 按 1899-12-30 基准换算；  
- 解析失败 → NULL；  
- 衍生：`established_year`、`company_age`（相对导入当日）。

## 7. 联系方式 → `contacts` 表

### 7.1 拆分

手机 / 更多电话 / 邮箱字段：按 `,，;；、空白|` 拆成多值（`split_multi`）。

### 7.2 校验与入库

| 类型 | 规则 | contact_type |
|------|------|-------------|
| 手机 | 抽取数字后匹配 `^1[3-9]\d{9}$` | `mobile` |
| 座机 | 数字长度 7–13；像手机的改走手机；保留原形（可含区号 `-`） | `landline` |
| 邮箱 | 标准邮箱正则；小写 | `email` |

- 同一企业同类型同值去重；  
- `source`：全量 `jzh2024`，月度 `monthly2025`，手工 `manual`；  
- `collected_at`：批次截止日（如全量 `2024-11-01`）；  
- 主表冗余：`has_mobile` / `has_landline` / `has_email` / `has_contact` / `mobile_count` / `email_count`。

### 7.3 通信地址

原文可能为 `地址A\t;\t地址B` → 拆分去重后用 ` | ` 拼接。

## 8. 街道解析（重要：多次调整后的定稿）

### 8.1 标准库

表 `admin_divisions`（高德 district **区划接口一次拉取**，非按企业计费）：

- 江浙沪皖四级：省 / 市 / 区 / 街；  
- 街道级带 `center_lng` / `center_lat`；  
- 当前约 **4401** 条街道。

### 8.2 匹配优先级（`street_utils.extract_street`）

1. **默认只走标准库最长匹配**（按市+区索引，街道名按长度降序）；  
2. 去掉地址前的省市区、高新区/开发区等前缀再匹配；  
3. 别名：地址写「××镇」可落到库中「××街道」等；  
4. **正则降级默认关闭**（`allow_regex_fallback=False`），避免再出现「淳化街道淳化镇」类脏名；  
5. 全量回填 `backfill_street.py`：**仅标准库命中才写入**。

### 8.3 脏名治理约定

- 禁止用宽松正则把半截地址当街道入库；  
- 下拉 / 地图聚合读标准库或已清洗的 `companies.street`；  
- UI 侧对历史脏街道曾加长度与模式过滤（兜底），根治靠标准匹配回填。

## 9. 地理坐标（地图用）

### 9.1 定稿：街道中心点回填（免费，地图主路径）

**原则：** 地图拓客只需街道/区县级精度，**禁止**对全库逐条调高德「地理编码 / 地址→坐标」API（按次计费）。  
坐标来自区划库里已有的 `center_lng` / `center_lat`（`load_admin_amap` 拉 district 时一次写入），企业侧只做匹配赋值。

脚本：`etl/geocode_by_street.py`（不读 Key、不打 geocode 接口）。

#### 9.1.1 候选企业

同时满足：

| 条件 | 说明 |
|------|------|
| `lng IS NULL` | 尚未有坐标 |
| `street` 非空 | 须先经 §8 标准库回填街道 |
| `status = '存续'` | 脚本默认只处理存续 |
| 可选 `--only-mobile` | 仅 `has_mobile = 1`（业务优先有手机） |

排序：`has_mobile DESC, capital_wan DESC`（有手机、资本大的优先）。

#### 9.1.2 命中顺序

1. **街道中心（主）**  
   键：`(province, city, district, street)` → `admin_divisions` 且 `level='street'` 的 `center_*`。  
   若省字段偶发不一致：同市+同区+同街道名也可命中，仍标 `geo_precision = street`。
2. **区县中心（回退）**  
   默认 `--fallback district`：街道未命中时用 `(省,市,区)` → `level='district'` 中心；  
   同样允许省不一致时按市+区回退。  
   `--fallback none` 则不做区县回退。
3. 仍无点 → 本批跳过（`miss`），不写库。

#### 9.1.3 写入字段

| 字段 | 规则 |
|------|------|
| `lng` / `lat` | 中心点；默认再经抖动（见下）后 `round(..., 6)` |
| `geo_precision` | `street` 或 `district` |
| `geocoded_at` | 本批写入时间 |
| `fill_score` | 原值 `+ 1`（覆盖 UNIQUE 旧行） |

写入方式：`companies` 表 **partial columns** Stream Load（只更新上述列）。

#### 9.1.4 同街道抖动（jitter）

同街道企业若共用同一中心点会完全重叠，地图上像「只有一家」。

- 按 `credit_code` 做 MD5 确定性偏移，默认半径约 **±120 米**（`--jitter 0` 可关）；  
- 非随机：同一信用代码每次回填落点相同。

#### 9.1.5 坐标系与精度边界

- 与 `admin_divisions` 中心一致：**GCJ-02**（高德）；  
- **不是门牌/楼栋精度**，只够气泡聚合、侧栏列表、可视区域点数；  
- 门牌级仅小样本/重点客户可选：`etl/geocode_amap.py`（按地址调高德，计费）。

#### 9.1.6 依赖与运维约定

1. 先保证 §8 街道为标准名（`backfill_street`），再跑本脚本；  
2. 可分批反复跑：`--limit` / `--batch`，直到「有街道无坐标」耗尽或可接受；  
3. 区划中心更新后，需重新跑脚本才会刷新企业坐标（旧点不会自动改）。

### 9.2 地图与列表口径

| 场景 | 口径 |
|------|------|
| 地图气泡计数 | 需有坐标（已定位）；市/区/街层按**行政区全量已定位**计，不与视野框裁切企业数 |
| 点气泡侧栏 | `require_geo=0`：**含未定位**企业 |
| 顶栏「可视区域 N 家」 | 当前视野框内已定位点数 |
| 街道及更细缩放 | **不再下钻网格/单企点**；地图只保留街道聚合气泡，点右侧列表才出定位针 |

## 10. 查询侧规则（非入库，但影响命中）

`api.classify_query`：

| 输入形态 | 类型 | 匹配方式 |
|----------|------|----------|
| 含 `@` | email | contacts 精确（小写） |
| 规范化后手机/7–12 位数字 | phone | contacts 精确 |
| 15–18 位字母数字 | credit | `credit_code` 精确 |
| 2–4 个汉字（无「公司/厂/店…」） | person | **`legal_person` 精确** 或公司名 LIKE；**禁止 MATCH_ANY 拆字** |
| 企业特征词 / ≥4 汉字 / 较长串 | company | **倒排 `MATCH_ALL` + `LIKE` 整段包含**（毫秒级）；禁止裸 MATCH_ANY / 裸 leading-wildcard LIKE |
| 其他短词 | keyword | 公司名 / 法人 `MATCH_ALL`（经营范围请用「经营范围关键词」） |

电话规范化：去空格与 `()-`，去掉 `+86` / `0086` / 首位 `86` 前缀。

地图与列表共用 `build_where`；`has_mobile=-1` 表示不限触达。
